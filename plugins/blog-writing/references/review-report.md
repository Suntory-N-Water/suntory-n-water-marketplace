# レビュー結果の出力契約

`article-review` と `tech-review` はこのファイルの全体を使う。`japanese-sentence-order` は「出力先」「場所」「件数」を使い、1 件ごとの項目は自身の `SKILL.md` に従う。

## 出力先

指摘の出力先は、レビューを依頼したユーザーへの最終応答とする。ユーザーが保存先を指定した場合だけ、そのパスにもレビューを保存する。保存先の指定がないときは、レビュー用のファイルを新しく作らない。

`bun run lint`、`gh run view`、テスト実行などの標準出力は検証の証拠であり、レビュー本文そのものではない。必要な行だけを根拠や検証記録に取り込み、ツールの出力をそのまま指摘一覧として返さない。

## 場所の示し方

行番号は編集でずれるため、指摘の場所を行番号だけで示さない。記事の相対パス、最も近い見出し、該当箇所の正確な引用を組み合わせる。

```text
場所: contents/blog/2026-09-04_pnpm-setup-migration.md > ## セットアップにかかる時間
該当箇所: 「pnpm/action-setup を使うと、セットアップだけで 7 分かかりました。」
```

コードは、記事の相対パス、見出し、コードブロックの言語またはファイル名、識別できるコードの引用で示す。frontmatter はフィールド名で示す。同じ文が複数ある場合は、前後の短い文を加えて一意にする。行番号を添える場合も、引用と見出しの補助として使う。

## 件数と順序

詳細な指摘は、読者への影響が大きい順に最大 5 件まで書く。重大度が同じ場合は、修正しないと読者が先へ進めないものを先にする。6 件目以降も省略せず、「追加の指摘」に重大度、場所、要点を 1 行ずつ並べる。根本原因が同じ指摘は 1 件にまとめる。

## 重大度

| 表示 | 基準 |
|---|---|
| 🔴 修正必須 | 手順どおりに進むと動かない、壊れる、安全に使えない |
| 🟠 公開前に修正 | 手順は動くが、現在の事実、観測条件、適用範囲を読者が誤認する |
| 🟡 改善の提案 | 読者が理解・判断・再現するための情報が不足している、または構成や表現を改善できる |
| ⚪️ 任意 | 好みの範囲の調整 |

## 書き換えの扱い

書き換えを依頼された場合、一次情報との不一致や実行結果との不一致のような事実の誤りは、追加の確認を取らずに修正する。構成、主張の強さ、節の追加・削除、扱う範囲、書き手の意見など、書き手の判断に属する変更だけは、変更前に確認する。事実を修正した結果として結論や観測条件の説明が変わる場合は、修正箇所と影響をまとめて報告する。
