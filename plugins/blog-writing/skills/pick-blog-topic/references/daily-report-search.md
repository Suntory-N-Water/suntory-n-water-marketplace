# Obsidian のデイリーレポートから題材の候補を探す

保管庫は作業フォルダの 1 つ上の階層にある `../sui-articles` とする。見つからない場合は探索せず、保管庫の場所を利用者に尋ねる。

## 読むデイリーレポート

`DailyReports/YYYY-MM/YYYY-MM-DD_daily_report.md` を読む。利用者が期間を指定しない場合は、直近 14 日分を読む。

デイリーレポートには、その日の次の内容がまとまっている。

| 見出し | 中身 |
|---|---|
| `## LINE Daily` | LINE から送った URL と一言の感想 |
| `## メモ` | 時刻付きの思いつき、疑問、試した結果 |
| `## Zettelkasten` | その日に作ったノートのタイトルとリンク。本文は含まない |

`## 資料` は過去のデイリーレポートへのリンクだけなので読まない。

## 元のメモを開く

デイリーレポートを作るスクリプト(`scripts/generate_daily_report.ts`)は、LINE Daily とメモの各項目を 5 行までに切り詰める。候補にする項目は、項目の上にある `- Obsidian: [[パス|名前]]` のパスに `.md` を付けて、元のファイルを開いて全文を読む。

`## Zettelkasten` のノートはタイトルしか載っていない。タイトルが LINE Daily やメモの話題と重なるとき、またはタイトルだけで利用者の経験や意見を書いたノートだと分かるときに、リンク先を開く。`LiteratureNote` は他人の記事のクリップなので、単独では候補にせず、根拠の資料として読む。

## 候補にする項目

同じ話題が複数の日に出てくるものを優先する。1 回だけ出てくる話題でも、次のどれかを含むものは候補にする。

- 利用者が実際に試したこと、その結果、想定との差
- 利用者自身の意見、疑問、違和感
- 書きかけの記事の構成や下書き

URL だけで感想がない項目、「うーん」「ほ？」のような一言だけの項目、旅行や買い物などの予定だけの項目は候補にしない。

## 候補の示し方

SKILL.md の手順 2 と同じ方法で、公開記事と記録済みの題材に同じ切り口がないかを確かめ、重なるものを除く。残った候補から 3〜5 件を選び、各候補に次の内容を添える。

- 話題が出てきたデイリーレポートの日付と、元のメモのパス
- 記事の切り口を 1 文で
- メモの中に揃っている材料
- 記事にするために足りないもの
