# 話題テスト、論証、見出しの付け方の適用手順

article-review の手順 3〜5 で使います。判定の基準と例文は ../../write-blog-article/references/sui-style.md の「話題テスト」「論証」「見出しの付け方」にあります。ここでは、それらを原稿へ適用する具体的な手順を定めます。

## 話題テスト（手順 3）

次の 2 種類の文を対象にします。

- 全段落の先頭の文
- 独立した短い文（1 行だけの段落、箇条書きの直前や直後に置かれた一文）

文ごとに sui-style.md の「話題テスト」の基準で判定します。その文が新しく伝えるのが対象そのもののこと（性質、データ、確かめた結果、書き手の判断の状態）であれば残します。この文章自体のこと（見え方、次に書くこと、何を書かないか）だけを伝えている文であれば指摘します。

指摘するときは、次の順で書きます。

1. 該当する文を引用します。
2. 「例外として残してよい 4 つの形」のどれにも当てはまらないことを確認して記載します。
3. 削除しても前後がつながるなら「削除」を修正案にします。論理が飛ぶなら、その文が指そうとしていた内容を対象の側の文に書き換えた案を出します。

修正案として新しく作成した文や短く分割した文についても、再度この話題テストを適用して確認します。

## 論証（手順 4）

sui-style.md の「論証」の各項目を、原稿の主張ごとに確かめます。

| 項目 | 原稿で確認する箇所 |
|---|---|
| 推量は推量のまま残す | 「〜の可能性があります」「〜と考えられます」が、本文の根拠で確定していないのに言い切る形に直されていないか |
| 区別すべき対象に別々の言葉を当てる | 別々の原因や決定を「同じ」「いずれも」でまとめていないか |
| 複数の要因を並べて書く | 1 つの原因だけに還元している説明がないか |
| 原因に理由を一文添える | 「A だと B になります」で理由が省かれていないか |
| 検出、保証、解決に条件を付ける | 「必ず」「常に」で成り立つ条件が抜けていないか |
| 節をまたいで概念の扱いを揃える | ある節の分類や用語が別の節で変わっていないか |
| 例が主張の全体を支えているか | 例が一部しか支えていないのに主張が広くなっていないか |

指摘には、どの項目に当てはまるかと、主張の範囲を適切に狭める案、または根拠を補う案を書きます。

## 見出しの付け方（手順 5）

## と ### の見出しをすべて抽出し、sui-style.md の「見出しの付け方」に沿って確かめます。

- その節が答える問い、または扱う対象を具体的に指しているか
- 作業の手順だけを述べる見出し（「〜を読み直す」など）や、内容が分からない見出しになっていないか
- 節の結論を言い切るセリフのような表現になっていないか

指摘には、その節で読者が何を知るのかを明確に表す見出しの修正案を添えます。疑問形か名詞句かは、本文の文脈に合う方を選びます。
