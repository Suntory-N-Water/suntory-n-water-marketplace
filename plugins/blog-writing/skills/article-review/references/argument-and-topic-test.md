# 話題テスト、論証、見出しの付け方の当て方

`article-review` の手順 3〜5 で使う。判定の基準と例文は `../../write-blog-article/references/sui-style.md` の「話題テスト」「論証」「見出しの付け方」にある。ここには、それを原稿にどう当てるかだけを書く。

## 話題テスト（手順 3）

次の 2 種類の文を対象にする。

- 全段落の先頭の文
- 独立した短い文（1 行だけの段落、箇条書きの直前や直後に置かれた一文）

文ごとに `sui-style.md` の「話題テスト」の軸で判定する。その文が新しく伝えるのが対象そのもののこと（性質、データ、観測した結果、書き手の判断の状態）なら残す。この文章自体のこと（見え方、次に書くこと、何を書かないか）だけなら指摘する。

指摘するときは、次の順で書く。

1. 該当する文を引用する
2. 「例外として残してよい 4 つの形」のどれにも当たらないことを確かめて書く
3. 削除で前後がつながるなら「削除」を修正案にする。論理が飛ぶなら、その文が指そうとしていた内容を対象の側の文に書き換えた案を出す

推敲で新しく書かれた文と、短く割り直した文は駄文の混入経路になる。書き換え案を出したあと、その案にもこのテストをかける。

## 論証（手順 4）

`sui-style.md` の「論証」の 7 項目を、原稿の主張ごとに確かめる。

| 項目 | 原稿で見る箇所 |
|---|---|
| 推量は推量のまま残す | 「〜かもしれません」「〜と考えられます」が、本文の根拠で確定していないのに断定に直されていないか |
| 区別すべき対象に別々の言葉を当てる | 別々の原因や決定を「同じ」「いずれも」でくくっていないか |
| 複数の要因を並べて書く | 1 つの原因に還元している説明がないか |
| 原因に、なぜそうなるかを一文添える | 「A だと B になります」で理由が省かれていないか |
| 検出、保証、解決に条件を付ける | 「必ず」「常に」で成り立つ条件が抜けていないか |
| 節をまたいで概念の扱いを揃える | ある節の分類が別の節で変わっていないか |
| 例が主張の全体を支えているか | 例が一部しか支えないのに主張が広くなっていないか |

指摘には、どの項目に当たるかと、主張の範囲を狭める案または根拠を足す案を書く。

## 見出しの付け方（手順 5）

`##` と `###` の見出しをすべて拾い、`sui-style.md` の「見出しの付け方」で確かめる。

- その節が答える問い、または扱う対象を指しているか
- 作業の手順だけを述べる見出し（「〜を読み直す」）や、情報量のない見出しになっていないか
- 節の結論を言い切る「セリフ」になっていないか

指摘には、その節で読者が何を知るのかを表す見出しの案を添える。疑問形か名詞句かは、本文のトーンに合うほうを選ぶ。
