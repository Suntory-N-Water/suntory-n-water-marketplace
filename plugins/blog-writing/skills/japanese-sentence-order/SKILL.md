# 日本語の一文の語順と読点を確認する

対象は一文の中だけとします。修飾語の順序、読点の位置、入れ子構造、助詞の使い分け、漢字とひらがなの割合を確認します。文体、構成、記事全体の表現は扱いません。

## 読み込む参照ファイル

- references/sentence-order.md: 日本語の作文技術に基づく規則。悪い例、良い例、規則を適用しない条件を作業の前に読みます。
- ../../references/review-report.md: 出力先、場所の示し方、件数の取り決めを作業の前に読みます。

## 手順

1. references/sentence-order.md と ../../references/review-report.md を読みます。
2. 対象の文章（貼り付けた本文、ファイル、下書きなど）を特定します。
3. 一文ずつ、次の順で確かめます。
   - 修飾語の順序。節を先に、長い修飾語を先に、大状況から小状況へ、結びつきの強い語を隣に配置します。
   - 読点の位置。長い修飾語が 2 つ以上あるときの境目、語順を逆にしたときの直後に打ちます。
   - 入れ子構造。主語と述語が離れている文、文の中に別の文が丸ごと入っている文を解消します。
   - 助詞の使い分け（「は」と「が」、「まで」と「までに」）。
   - 漢字とひらがなの割合。
4. ../../references/review-report.md の出力先、場所、件数の取り決めに従って指摘を返します。

## 適用しない条件

references/sentence-order.md の「この規則の適用条件」に従います。指示語と形容詞と名詞の組み合わせ（「この快適な開発体験」など）、長さの差が小さい単語同士、規則を当てると不自然になる文はそのまま残します。

## 出力

詳細な指摘は最大 5 件まで書き、残りは「追加の指摘」にまとめます。1 件ごとに次の 3 項目を書きます。対象の文は、記事の相対パスと見出しも添えて、行番号だけに依存しないようにします。

```
対象の文: （そのまま引用）
読みにくい理由: 何が何にかかるか曖昧、主語と述語が遠い、など。根拠にした規則の名前を添える
書き換えた文: 意味と書き手の表現を変えずに語順と読点だけを直した文
```

- 意味、固有名詞、数値、文末の敬体と常体は変えません。
- 指摘が 0 件の場合はその旨を伝え、確認した文の数を書きます。
- 原稿の書き換えは、依頼された場合だけ行います。

## 校正ツールとの分担

文章校正ツール（textlint など）で機械的に確認できる範囲（文字数や禁止用語など）と分担し、修飾語の順序、入れ子構造、論理的な読点の位置など、文脈判断が必要な部分をこのスキルが担当します。

## 他のスキルへ渡す場面

- 文体の統一、段落の構成、まとめと本文の一致、使わない言い回しの確認は article-review に渡します。
- 技術的な正しさの確認は tech-review に渡します。
