# 日本語の一文の語順と読点を確認する

対象は一文の中だけ。修飾語の順序、読点の位置、入れ子構造、助詞の使い分け、漢字とひらがなの割合を見る。文体、構成、記事全体の言い回しは扱わない。

## 読み込む references

- `references/sentence-order.md`: 本多勝一『日本語の作文技術』を元にした規則。悪い例、良い例、規則を適用しない条件まで書いてある。作業の前に読む
- `../../references/review-report.md`: 出力先、場所の示し方、件数。作業の前に読む

## 手順

1. `references/sentence-order.md` と `../../references/review-report.md` を読む
2. 対象の文章（貼り付けた本文、ファイル、生成中の下書き）を特定する
3. 一文ずつ、次の順で確かめる
   - 修飾語の順序。節を先に、長い修飾語を先に、大状況から小状況へ、親和度の強い語を隣に
   - 読点の位置。長い修飾語が 2 つ以上あるときの境目、語順を逆にしたときの直後
   - 入れ子構造。主語と述語が離れている文、文の中に別の文が丸ごと入っている文
   - 助詞の使い分け（「は」と「が」、「まで」と「までに」）
   - 漢字とひらがなの割合
4. `../../references/review-report.md` の出力先、場所、件数に従って指摘を返す

## 適用しない条件

`references/sentence-order.md` の「このルールの適用条件」に従う。指示語と形容詞と名詞の組み合わせ（「この快適な開発体験」）、長さの差が小さい単語同士、規則を当てると不自然になる文はそのまま残す。

## 出力

詳細な指摘は最大 5 件まで書き、残りは「追加の指摘」にまとめる。1 件ごとに次の 3 つを書く。対象の文は、記事の相対パスと見出しも添えて、行番号だけにしない。

```
対象の文: （そのまま引用）
読みにくい理由: 何が何にかかるか曖昧、主語と述語が遠い、など。根拠にした規則の名前を添える
書き換えた文: 意味と書き手の言い回しを変えずに語順と読点だけを直した文
```

- 意味、固有名詞、数値、文末の敬体と常体は変えない
- 指摘が 0 件の場合はその旨を伝え、確認した文の数を書く
- 原稿の書き換えは、依頼された場合だけ行う

## textlint との分担

sui-blog の textlint 設定では、一文の長さの検査（`sentence-length`）と助詞の連続の検査（`no-doubled-joshi`）を無効にしてあり、漢字の連続は 10 文字まで許容している。修飾語の順序、入れ子構造、読点の位置は textlint の検査範囲の外にあるため、このスキルがその部分を担当する。

## 他のスキルへ渡す場面

- 文体の統一、段落の構成、まとめと本文の一致、使わない言い回しは `article-review` に渡す
- 技術的な正しさは `tech-review` に渡す
