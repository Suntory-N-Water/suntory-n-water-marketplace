# 記事の構成と日本語を確認する

原稿を読み、読者が追える構成になっているか、日本語が `sui-style.md` に沿っているかを確かめて指摘を返す。原稿の書き換えは、依頼された場合だけ行う。

## 読み込む references

| ファイル | 読むタイミング |
|---|---|
| `../write-blog-article/references/sui-style.md` | 手順 1。文体、使わない言い回し、論証、見出しの付け方、話題テストの規範本体 |
| `references/editorial-checklist.md` | 手順 2 の確認項目 |
| `references/argument-and-topic-test.md` | 手順 3〜5 の進め方 |

規範の本体は `sui-style.md` の 1 ファイルにある。このスキルの references には、それをどの順で原稿に当てるかだけを書いてある。

## 手順

1. 原稿の全体と `../write-blog-article/references/sui-style.md` を読む
2. `references/editorial-checklist.md` の項目を順に確かめる。`title` と `description`、導入、見出しの順序、概念の依存関係、段落、指示語、コードと画像とリンクの前後、証拠の有無、再現できる情報、`## まとめ`、文体と表記と用語を見る
3. `references/argument-and-topic-test.md` に従い、話題テストを全段落の先頭の文と、独立した短い文に適用する
4. 「論証」の各項目を確かめる
5. 「見出しの付け方」を確かめる
6. 「使わない言い回し」を原稿から検索する
7. `contents/` で `bun run lint`（textlint）を実行し、その結果も指摘に含める
8. `ai-police` サブエージェントへ原稿を渡し、独立した判断で確認させる。サブエージェントが無い環境では、その旨を報告に書く
9. 指摘を返す

## 記事本文と検証用ディレクトリの関係

記事本文には、読者が自分の環境だけで再現できる情報を書く。`examples/<slug>/` は書き手の作業場所であり、読者の手元には届かない。ローカルのパス、ディレクトリ名、そこでの起動コマンド、リポジトリの場所が本文にあれば指摘し、観測した条件と結果に置き換える案を出す。

- 改善前: 「検証用サンプルでは 40 秒でした」
- 改善後: 「キャッシュを無効にした状態で実行したところ、40 秒でした」

## 指摘の形式

重大度の順に並べる。

```
🔴 修正必須: 短い見出し
場所: contents/blog/2026-09-04_pnpm-setup-migration.md:42
読者への影響: 読者が何を誤解するか、何ができないか
修正案: 具体的な置き換え、移動、削除、書き直し
```

重大度は 4 段階にする。

| 表示 | 意味 |
|---|---|
| 🔴 修正必須 | 記事が使えない、または読者を誤らせる |
| 🟠 公開前に修正 | 公開までに直すべき構成または日本語の問題 |
| 🟡 改善の提案 | 読みやすさが上がる |
| ⚪️ 任意 | 好みの範囲の調整 |

- 同じ問題が繰り返し現れる場合は 1 件にまとめる
- 指摘が 0 件の場合はその旨を伝え、確認できた範囲を書く
- 褒める節は、依頼された場合だけ書く

## 書き換えを依頼された場合

意味と書き手の言い回しを保ったまま適用する。主張、技術的な内容、扱う範囲、書き手の意見を変える必要が出た場合は、先に断って承認を得る。

## 他のスキルへ渡す場面

- コードが動くか、バージョンの記載が正しいか、一次情報と一致するかは `tech-review` に渡す
- 一文の中の修飾語の順序と読点だけを細かく見たい場合は `japanese-sentence-order` に渡す
- 記事がまだ無く、これから書く相談なら `write-blog-article` に切り替える
