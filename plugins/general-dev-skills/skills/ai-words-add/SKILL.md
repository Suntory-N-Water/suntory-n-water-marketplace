# ai-words 辞書へ語を 1 件登録する

指摘を受けたそのターンで、語を 1 件だけ辞書へ反映する。形態素解析で一致を見るため、活用形もまとめて拾える代わりに、思った形態素に割れているかを実際に確かめないと当たらない。確認を飛ばさない。

## この仕組みの構成

- `~/.claude/.textlintrc.json` の `preset-ai-words-ja` → `no-ai-words` が語の検出を行う
- 自作辞書は `~/.claude/ai-words.json`。`dictionaryPath` で読み込まれ、内蔵辞書に**追加**される（内蔵の語は消せない）
- `~/.claude/scripts/typescript/textlint-post-tool-use.ts` が PostToolUse フックとして `.md` の Write / Edit を見て、その編集で増えた指摘だけを Claude へ返す

フックは `message` の文面だけを Claude に渡す。だから `message` に「どう書き直すか」を書いておかないと、指摘を受けた側は直しようがない。

編集前に `.textlintrc.json` と `ai-words.json` の現物を読む。構成は別のタスクで変わっていることがある。

## 確認用スクリプト

```bash
bun run ~/.claude/scripts/typescript/ai-words.ts tokens "例文"
bun run ~/.claude/scripts/typescript/ai-words.ts lint "例文" "別の例文"
```

- `tokens`: kuromoji がその文をどう割ったかを `surface_form` / `pos` / `pos_detail_1` / `basic_form` で表示する
- `lint`: 今の `.textlintrc.json` の設定で例文を textlint にかける。複数の例文をまとめて渡せる

スクリプトはこのプラグインではなく `~/.claude` 側に置いてある。フックが実際に使うのと同じ textlint・同じプリセットで確かめないと確認にならないためで、別に入れた textlint では結果が変わりうる。どのディレクトリから実行しても結果は同じ。

スクリプトが見つからない場合は、推測で別の場所を探さずユーザーへ確認する。

## 登録する（語を指摘させたい）

### 1. 語を 1 つに絞り、例文を作る

ユーザーの指摘から、禁止したい語と言い換え先を取り出す。複数の語をまとめて登録しない。

ユーザーが実際に不快に感じた文をそのまま例文にする。あわせて、同じ語形を含むが指摘させたくない文（別の意味で使う文）も 1 つ用意する。この 2 つが後の確認材料になる。

### 2. すでに検出されるか確かめる

```bash
bun run ~/.claude/scripts/typescript/ai-words.ts lint "例文"
```

内蔵辞書がすでに拾っているなら、辞書は変えずにその旨を伝えて終了する。二重登録は同じ箇所に 2 件の指摘を出す。

### 3. 形態素を確かめる

```bash
bun run ~/.claude/scripts/typescript/ai-words.ts tokens "例文"
```

出力を見て、狙った語がいくつの形態素に割れているかを確認する。ここを想像で書くと当たらない。

たとえば `立ち上げる` は 1 語ではなく、`立ち`（動詞・自立・`basic_form` は `立つ`）と `上げ`（動詞・**非自立**・`basic_form` は `上げる`）の 2 形態素に割れる。`{ "basic_form": "立ち上げる" }` と書いても永遠に一致しない。

### 4. `entries` に 1 件追記する

`ai-words.json` の `entries` 末尾に追記する。既存の順序や書式は変えない。

```json
{
  "message": "\"立ち上げる\" は避ける。「開始する」など具体的な動作を書く。",
  "tokens": [
    { "pos": "動詞", "pos_detail_1": "自立", "surface_form": "立ち" },
    { "pos": "動詞", "pos_detail_1": "非自立", "basic_form": "上げる" }
  ]
}
```

`tokens` は形態素の並びで、全部が連続して一致したときだけ指摘になる。書き方の指針は次のとおり。

- 動詞は `{ "pos": "動詞", "pos_detail_1": "自立", "basic_form": "…" }`。`basic_form` で書けば活用形もまとめて一致する
- 名詞は `{ "pos": "名詞", "basic_form": "…" }`
- 辞書にない語（新しいカタカナ語など）は `basic_form` が `*` になることがある。`tokens` の出力がそうなっていたら `surface_form` で書く
- `surface_form` には配列も渡せる。`{ "surface_form": ["走る", "走っ", "走り"] }` のように、一致させたい表層形だけを並べて範囲を狭められる
- 1 文字の語や別の意味で頻繁に使う語は、そのままだと巻き込みが大きい。前後の助詞を足して意味を限定する。`{ "pos": "助詞", "pos_detail_1": "格助詞", "surface_form": "に" }` を先頭に置くと `〜に落ちる` のような形だけを拾える

`message` には禁止だけでなく書き直し方を入れる。ユーザーが言い換え先を示したなら、その語をそのまま使う。示していないなら、その語を使いたくなる場面で何と書けばよいかを具体的に書く。ユーザーの意図が読み取れない場合は、`message` を作る前に言い換え先を確認する。

内蔵辞書に合わせるなら文面は `"X" はAIが書いた文章で多用される表現です。別の表現に言い換えられないか検討してください。` の形になるが、書き直し先が決まっているならそちらを優先する。

### 5. 当たっているか確かめる

```bash
bun run ~/.claude/scripts/typescript/ai-words.ts lint "指摘させたい例文" "指摘させたくない例文"
```

指摘させたい文で 1 件出て、指摘させたくない文で出ないことを確認する。片方でも外れていたら `tokens` を直して再実行する。確認せずに完了を報告しない。

なお、フックは編集で**増えた**指摘だけを返すため、登録した語が既存ファイルに遡って出ることはない。動作確認はこのスクリプトで行う。

## 除外する（指摘を止めたい）

textlint に指摘されたがその語を使い続けたい場合は、`.textlintrc.json` の `allows` へ追加する。

```json
{
  "rules": {
    "preset-ai-words-ja": {
      "no-ai-words": {
        "dictionaryPath": "./ai-words.json",
        "allows": ["経路", "/検査|部品/"]
      }
    }
  }
}
```

`allows` は**一致した文字列**に対して判定する。文全体ではない。`"経路"` を入れるとその語の指摘はすべて止まる。文脈によって残したいという要望には応えられないので、その場合は全部止めてよいかをユーザーに確認する。

`/…/` の形にすると正規表現として扱われる。`g` フラグは無視される。

自作辞書で追加した語を止めたいだけなら、`allows` ではなく `entries` から該当の 1 件を消すほうが素直。

変更後は `lint` で、止めたい文から指摘が消え、他の語の指摘は残っていることを確認する。

## 登録しないもの

次は `no-ai-words` では表現できない。ファイルを変えず、理由を伝えて終わる。

- 「冗長」「話が飛んでいる」のような、文章全体や論理関係への評価
- 文書全体を数えないと判定できないもの（同じ語の使いすぎなど）
- 語ではなく記法の好み。箇条書きの形、見出しの強調、コロンの使い方は `@textlint-ja/preset-ai-writing` 側の担当なので、`.textlintrc.json` のそちらのルール設定を見る

会話履歴を遡って候補をまとめて抽出することもしない。指摘を受けた 1 件だけを扱う。

## 報告

登録できたときは、登録した語、`tokens` をその形にした理由（形態素の割れ方で判断が要った場合）、`message` に入れた書き直し先、確認に使った例文と結果を簡潔に伝える。

登録しなかったときは、変更していないことと理由を伝える。
