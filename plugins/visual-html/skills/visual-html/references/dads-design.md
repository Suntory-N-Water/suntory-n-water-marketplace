# デジタル庁デザインシステムに沿ったデザイン

visual-html が作るHTMLは、デジタル庁デザインシステム(DADS)の色、文字、余白、コンポーネント(ボタンやカードなど画面の構成要素)の考え方に沿わせる。DADS は読みやすさとアクセシビリティを優先する体系で、装飾より情報の伝わりやすさを重んじるため、仕様書や調査レポートのような読み物に合う。

出典(値や方針が正しいか確かめたいときは、ここを確認する):

- デザインシステム: https://design.digital.go.jp/dads/
- デザイントークン(CSS): https://github.com/digital-go-jp/design-tokens の `examples/tokens.css`
- 解説ページ: https://www.digital.go.jp/policies/servicedesign/designsystem

`assets/dads.css` は、この文書の内容を実装したスタイルシートで、`scripts/build_html.py` が HTML に埋め込む。新しいコンポーネントが必要になったら、この文書の規則に沿って `dads.css` に追加する。

クラス名は次のとおり付ける。

- 原本(https://github.com/digital-go-jp/design-system-example-components-html の `src/components/`)に同名のコンポーネントがあるものは、原本のクラス名(`dads-list`、`dads-step-navigation` など)と `data-*` 属性をそのまま使う。原本の CSS と並べて差分を確かめられるようにするため。
- 原本にまだ実装がないもの(注釈ブロックなど)と、このスキル独自のもの(要点ボックス、カードの数値表示など)は、従来の `.summary-box` `.card` のような名前にする。
- 原本から外した部分(リンクやボタンの状態、先頭に戻るリンクなど)と、原本にない追加は、`dads.css` のコメントに書く。

## このスキルでの前提

- 外部CDNとWebフォントは読み込まない。DADS は Noto Sans JP を採用しているが、OSのシステムフォントの使用は制限していない。そのため `font-family` の先頭に `'Noto Sans JP'` を書き(利用者の端末にあれば使われる)、ない場合は Hiragino Sans、Yu Gothic UI、Meiryo の順に切り替わるようにしている。
- 色と寸法は、`tokens.css` の変数名(`--color-primitive-blue-900` など)をそのまま使う。変数名を変えないと、値の出どころを後から追える。
- 内容に使わない色の変数は、HTMLから削ってよい。

## 色

青を基調に、グレーと意味を持つ色(セマンティックカラー)だけを使う。DADS の色は、背景とのコントラスト比を守れるように明度が段階づけられているため、段階の数字を勝手に動かすと基準を満たせなくなる。

| 用途 | 変数 | 値 |
| --- | --- | --- |
| 本文 | `--color-neutral-solid-gray-900` | `#1a1a1a` |
| 補足文(注記、メタ情報) | `--color-neutral-solid-gray-700` | `#4d4d4d` |
| 背景 | `--color-neutral-white` | `#ffffff` |
| 淡い面(表の見出し、コード) | `--color-neutral-solid-gray-50` | `#f2f2f2` |
| 区切り線、枠線 | `--color-neutral-solid-gray-200` | `#cccccc` |
| 強い区切り線(非テキストで3:1が要る場合) | `--color-neutral-solid-gray-420` | `#949494` |
| プライマリー(見出しの線、強調、図の主役) | `--color-primitive-blue-900` | `#0017c1` |
| リンク | `--color-primitive-blue-1000` | `#00118f` |
| 訪問済みリンク | `--color-primitive-magenta-900` | `#8b008b` |
| 要点ボックスの背景 | `--color-primitive-blue-50` | `#e8f1fe` |
| 成功、完了 | `--color-primitive-green-800` | `#197a4b` |
| 警告、注意 | `--color-primitive-orange-800` | `#c74700` |
| エラー、危険 | `--color-primitive-red-900` | `#ce0000` |

守る規則:

- テキストと背景のコントラスト比は4.5:1以上にする。枠線、アイコン、図の線は隣接する色に対して3:1以上にする。白地に使える最も明るいグレーは、テキストが `solid-gray-536`(`#767676`)、非テキストが `solid-gray-420`(`#949494`)。
- 色だけで意味を伝えない。ステータスや重要度は、`成功` `注意` `未確認` のような文字、またはアイコンを必ず併記する。色覚の違いで見分けられない利用者がいるため。
- 青以外の色を、装飾として使わない。緑、オレンジ、赤はセマンティックカラーとして、成功、警告、エラーの意味があるときだけ使う。
- グラデーションと影は装飾として使わない。DADS のエレベーション(影)は、ダイアログなど他の要素に重なるコンポーネントのためのもの。

## 文字

- 書体は `var(--font-family-sans)`、コードは `var(--font-family-mono)`。
- 本文は16px(`1rem`)、行間は1.7、字間は `0.02em`。注記は14px(`0.875rem`)まで。それより小さくしない。
- 見出しは太字(700)。大きさは h1 が36px(行間1.4)、h2 が28px(行間1.5)、h3 が20px。スマホでは h1 を28px、h2 を24px にする。
- 日本語本文を欧文用の小さな行間にしない。読む量が多い資料ほど、行間1.7で行の区切りが見分けやすくなる。
- リンクは青の下線つきにし、色だけで見分けさせない。フォーカス時は黒の4pxの枠線と黄色(`yellow-300`)の縁取りを出す。この組み合わせは DADS が「いかなる場合も変更してはいけない」としている。

## 余白と形

- 余白は8pxの倍数を基本にする(8、16、24、32、48、64)。
- 角丸は、カードと枠が `--border-radius-12`、要点ボックスや表の外枠が `--border-radius-8`、ラベル(タグ)が `--border-radius-4`。
- 画面幅の1080pxを最大幅にし、スマホでは左右16px、PCでは24pxの余白を取る。
- ガター(カラム間の余白)は、本文の文字サイズの2倍(約32px)を目安にする。狭いと隣の列の文字が近づいて読み違えやすくなるため。

## コンポーネント

`build_html.py` の各ブロック(`SKILL.md` の「ブロックの選び方」)が、次のコンポーネントを出力する。内容に合うものだけ使い、空のセクションは作らない。

| コンポーネント | クラス | 使いどころ |
| --- | --- | --- |
| スキップリンク | `.skip-link` | 常に置く。キーボード操作で本文へ移動できる |
| ヘッダー | `.site-header` | 組織名や資料の種別と日付 |
| タイトル領域 | `.page-title` `.eyebrow` `.lead` | 資料の種類、題名、1〜2文の要約 |
| 目次 | `.toc` | セクションが5つ以上のとき。見出し「このページの目次」の下に、見出しの文言そのままの項目を番号付きで並べる。原本の目次は縦1列の枠だが、セクションが多いと右側が空いたまま縦に長くなるため、本文幅いっぱいに最大3段で段組みする(上から下へ読む順)。見出しは削除しない |
| 要点ボックス | `.summary-box` | 結論と重要な判断。青い左線つき |
| カード | `.cards` `.card` | 数値、選択肢、要点。`.card--emphasis` で推奨案を枠で強調する |
| チップラベル | `.tag--success` `--info` `--warning` `--error` `--gray` | 状態を短い文字で示す。色と文字をセットにする。`gray` は未着手や対象外のように良し悪しを伴わない状態に使う。表のセルには `[[kind\|文字]]` で置く |
| ステップナビゲーション | `.dads-step-navigation` | 手順、業務フロー、進捗。状態(完了、到達済み、編集中、エラー、スキップ)は番号の下に文字でも出す。縦向きが既定、3〜4ステップの短いものは横向き |
| 箇条書きリスト | `.dads-list` | 項目の列挙。番号付きは `<ol>`、入れ子にできる |
| 説明リスト | `.dads-description-list` | 用語と説明、項目名と値のペア |
| 引用ブロック | `.dads-blockquote` | 原文や発言の引用。灰色の太い左線つき。本文の強調には使わない |
| ディバイダー | `.dads-divider` | 主題が変わる箇所の区切り線(`<hr>`) |
| アコーディオン | `.dads-accordion` | 同種の項目が並ぶ折りたたみ。中に他のブロックを入れられる |
| リソースリスト | `.dads-resource-list` | 参考資料や成果物の一覧。タイトル、ラベル、補足文、右端の補助情報を持つ |
| ノティフィケーションバナー | `.banner--success` `--warning` `--error` | リスク、未決事項、重要な注意。アイコン、見出し、本文を持たせる |
| 表 | `.table-wrap` `table` | 比較、API、要件。`th` に `scope` を付け、数値の列は `.num` で右揃えにする |
| 図 | `figure` `svg` `figcaption` | フロー図、構成図。`<title>` と `<desc>` で文章による代替を付ける |
| グラフ(棒、折れ線) | inline SVG、またはCSSの `.bar-track` | 数値の比較や推移。棒は色の差に加えて数値を文字で表示する |
| 折りたたみ | `details` `summary` | 原文、グラフの元データ表 |

### 使っていない原本のコンポーネント

次のコンポーネントは、このスキルが作る静的な単一HTMLに合わないため、`build_html.py` に実装していない。

- 入力と操作が必要なもの: ボタン、インプットテキスト、テキストエリア、セレクトボックス、コンボボックス、チェックボックス、ラジオボタン、スイッチ、日付ピッカー、ファイルアップロード、検索ボックス、テーブルコントロール、モーダルダイアログ、ドロワー、タブ。
- サイトの画面構成に使うもの: ヘッダーコンテナ、水平メニュー、メガメニュー、メニューリスト、メニューリストボックス、ハンバーガーメニューボタン、モバイルメニュー、ボトムナビゲーション、パンくず、ページナビゲーション、スクロールトップボタン、ユーティリティリンク、ランゲージセレクター、緊急時バナー。
- 画像を使うもの: 画像、イメージスライダー、カルーセル。外部の画像に依存しない方針のため。
- 処理中を表すもの: プログレスインジケーター。静的な資料に処理中の状態がないため。数値の達成度は `bars` で示す。
- 注釈ブロック: 原本のHTML版に実装がなく(2026年11月時点で「提供予定」)、枠線の色や余白の値を確かめられないため。補足情報は `banner`(`info`)か `summary` で示す。

### 表現の選び方

- グラフは、数値を必ず文字でも出す(棒の端やラベルに数値を置く)。色や長さだけだと、正確な値を読み取れないため。
- グラフの下に `<details>` で元データの表を置くと、スクリーンリーダーの利用者も値を読める。
- 比較の「推奨案」だけ `.card--emphasis`(青の太枠)にし、他の案はふつうのカードにする。複数を強調すると、どれが結論か分からなくなる。

## 手書きSVG(`figure` ブロック)

`flow`、`cards`、`bars` で表せない構成図だけ、SVG を手書きする。手書きした SVG は `dads.css` の色の変数を参照できないため、色の値を直接書く。次の値以外を使わない。

| 用途 | 塗り(fill) | 線(stroke) |
| --- | --- | --- |
| 主役の箱 | `#e8f1fe` | `#0017c1` |
| 成功、完了の箱 | `#e6f5ec` | `#197a4b` |
| 警告、注意の箱 | `#ffeee2` | `#c74700` |
| エラー、危険の箱 | `#fdeeee` | `#ce0000` |
| 中立の箱 | `#f2f2f2` | `#949494` |
| 矢印、接続線 | なし | `#4d4d4d` |

- 箱の中の文字は `#1a1a1a`、大きさは14px以上にする。濃い塗り(`#0017c1` など)の上に文字を置くときだけ `#ffffff` にする。
- `#7b9fff` や `#fe3939` のような明るい中間色を、塗りや棒に使わない。白い文字を重ねても、背景とのコントラスト比が4.5:1に届かない。
- 箱や棒の意味は、色に加えて箱の中の文字でも書く(「構築: 重い」など)。
- 手順の番号は `flow` ブロックが自動で付けるため、`flow` の `label` に「1」「2」のような番号を書かない。`label` には「第1週」のような日付や期間を書く。

## 仕上げの確認

- 本文の色が `#1a1a1a`、背景が白で、注記が `#4d4d4d` 以上に濃い。
- 見出しの階層(h1 は1つ、h2、h3)が飛んでいない。
- ステータスや重要度が、色だけでなく文字でも示されている。
- 図に `<title>` と `<desc>` がある。
- 青(プライマリー)とグレー以外の色が、セマンティックカラーとしての意味を持つ場所にしか出ていない。
